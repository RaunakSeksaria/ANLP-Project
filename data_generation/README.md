# data_generation/

How the three released datasets were built: BigNewsAlign events with a full
left / centre / right trio, and neutral targets generated by
`nvidia/nemotron-3-ultra-550b-a55b`. The finished datasets are on Hugging Face
(`RaunakSeksaria/anlp-project-datasets`); you only need this folder to
regenerate or extend them. `splits/` at the repo root rebuilds the training
splits from the HF copies.

`neutralize/` is the library (prompts, API clients, config, evaluation);
`scripts/` holds the entry points. Run everything from this folder:

```bash
cd data_generation
uv run python scripts/<name>.py --help
```

Inputs live in `data_generation/data/` and generation outputs in
`data_generation/runs/`; both are gitignored.

## Pipeline

```
  data/final/bignewsalign_max250_LCR.jsonl        BigNewsAlign export, 1 article per line
        |
        |  make_clusters.py           dedupe, group into events, shortest-first
        v
  data/final/clusters_*.jsonl                     1 event per line, L + C + R
        |
        +--> prepare_bignews.py       split assignment by connected component
        |                             -> data/prepared_bna/articles.jsonl
        |
        +--> generate_neutral.py      one neutral article per event      -> runs/nemotron/
        |         |
        |         +--> build_release_jsonl.py   inputs + neutral article + split
        |                                       -> neutral_articles_10k.jsonl   (HF: neutralised_across_articles)
        |
        +--> make_single_article_inputs.py      one article per record, per stance
                  |                             -> data/final/single_{left,right}_10k.jsonl
                  +--> generate_neutral.py --task neutralise
                  +--> make_extra_articles.py   extra train-only articles
                  +--> build_single_release.py --dedupe
                                                -> {left,right}_neutral_dedup.jsonl
                                                   (HF: reframing_left / reframing_right)
```

Run `validate_corpus.py` after building any corpus, and `eda_neutralised.py` on a
single-article release for its quality audit.

## Scripts

| script | what it does |
| --- | --- |
| `make_clusters.py` | Raw export → event clusters. Deduplicates (about 30% of the raw export is exact-duplicate events under different ids), filters copy-tasks, takes the shortest N. |
| `prepare_bignews.py` | Assigns train/val/test **by connected component** over shared articles and writes `data/prepared_bna/articles.jsonl`, which every later split inherits. |
| `generate_neutral.py` | The generation driver. Resumable, checkpointed per record, separate retry budgets. `--task fuse` (many articles → one) or `--task neutralise` (one article → the same article without framing). `--provider gemini\|nvidia`. |
| `build_release_jsonl.py` | Joins inputs, generated articles and splits into `neutral_articles_10k.jsonl`. |
| `make_single_article_inputs.py` | Expands clusters to one article per record, one file per stance. |
| `make_extra_articles.py` | Selects extra train-only articles, screened against every val/test article (word 5-gram Jaccard < 0.8). |
| `build_single_release.py` | Builds `{left,right}_neutral_dedup.jsonl`: one record per unique article (`--dedupe`). |
| `eda_neutralised.py` | Quality audit of a single-article release (attribution verbs, entities, quotations, length, known issues). |
| `validate_corpus.py` | Exits non-zero on misalignment, stray line breaks, duplicate ids, target-in-source leakage, or articles crossing a split. |
| `audit_summaries.py` | Quality audit of generated multi-source articles. |
| `check_consistency.py` | Re-runs a random sample under the recorded config and compares. `--similarity module:func` takes your own scorer. |

Production runs used the shell wrappers next to them: `run_nemotron_10k.sh` and
`watchdog.sh` (fusion), `run_neutralise.sh`, `watchdog_neutralise.sh` and
`supervise_neutralise.sh` (single-article), and `run_slice.sh` (extra articles).
They pin the flags of the released runs and restart a run if the endpoint drops.

## Running a generation job

Always `--dry-run` first: it renders the prompt for the first record and exits
without an API call. Keys come from `.env` at the repo root (`.env.example`).

```bash
uv run python scripts/generate_neutral.py \
  --provider nvidia --api-key-env NVIDIA_API_KEY \
  --model nvidia/nemotron-3-ultra-550b-a55b \
  --in data/final/clusters_corpus10k.jsonl --out runs/nemotron/out.jsonl \
  --workers 14 --rpm 40 --thinking-level HIGH --temperature 1.0 --top-p 0.95

uv run python scripts/generate_neutral.py --task neutralise \
  --provider nvidia --api-key-env NVIDIA_API_KEY \
  --in data/final/single_left_10k.jsonl --out runs/nemotron/neutralised_left.jsonl
```

## Things that will bite you

- **Splits are by connected component, not random.** Many events share an
  article with another event, so a random re-split puts the same text in train
  and test. Use the `split` field as provided.
- **Line-break characters are not just `\n`.** Bodies contain `\r`, ` ` and
  ` `; `str.splitlines()` breaks on them and silently shifts every later
  target against its source. All writers here strip
  `"\n\r\v\f\x1c\x1d\x1e\x85  "`. Do the same in your own.
- **Multi-source targets are longer than one input article** (median 215 words):
  this is fusion, not compression.
- **`--stop-after` aborts the run**, and unattempted records are dropped, not
  recorded. If a run stops early the endpoint is unhealthy; fix that, then resume.
- **Publisher determines stance completely** in this corpus: no outlet appears on
  more than one side.
